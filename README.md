# 인연노트 — 추천 상대와 그 이유를 보여주는 소개팅 앱

회원가입(5단계)에서 내 프로필, 이상형, 절대 안 되는 조건을 입력하면 가상 회원 20명 가운데에서 상대를 추천합니다.

| 화면 | 내용 |
|---|---|
| 가입 | 기본 정보 → 생활·가치관 → 관심사 → 자기소개 → 이상형 → 절대 조건 |
| 오늘의 추천 | 궁합 1위 카드 + "왜 이 분이 1위인가요?" + 다른 추천 목록 |
| 프로필 상세 | 기본 정보, 겹치는 관심사, 항목별 궁합 점수와 근거, 관심 보내기 |
| 매칭 리포트 | 거르기 단계별로 걸러진 사람과 이유, 점수표, 전체 순위 |
| 내 정보 | 내 프로필·이상형·절대 조건 수정, 보낸 관심 목록 |

**매칭과 채팅**
- 추천된 분에게 '관심 보내기'를 누르면, **궁합 점수가 50점 이상일 때 상대도 수락해 매칭**됩니다. 50점 미만이면 '답을 기다리는 중'으로 남습니다.
  가상 회원은 직접 답할 수 없어서 같은 궁합 점수를 상대의 마음으로 봅니다. 기준값은 `js/rules.js`의 `MATCH_RULE`에 있습니다.
- 매칭되면 상대가 먼저 인사를 보내고, '채팅' 탭에서 대화합니다.
- 가상 회원은 모두 **AI 캐릭터**이고 자기 프로필(직업, 지역, 관심사, 말투)대로 답합니다.
  - **기본 대화:** API 키 없이 바로 쓸 수 있습니다. 프로필을 바탕으로 한 규칙형 대답입니다.
  - **AI 대화:** '내 정보 → AI 대화 설정'에서 AI 종류를 고르면 LLM이 캐릭터를 연기합니다.
    - **Claude:** API 키를 넣으면 Claude(`claude-opus-5-5`, effort `low`)를 씁니다. 공식 SDK(`@anthropic-ai/sdk@0.129.0`)를 CDN에서 불러와
      브라우저에서 바로 호출하고, 안전 거절이 나오면 다른 모델로 넘기는 `fallbacks: "default"`가 켜져 있습니다.
    - **로컬 AI (Ollama):** 내 PC에서 돌아가는 Ollama를 씁니다. 키와 요금이 없고 대화가 PC 밖으로 나가지 않습니다.
    - **AI 서버:** 인연노트 AI 서버([`server/ai-server.mjs`](server/ai-server.mjs))를 거쳐 서버 주인의 Ollama를 씁니다.
      GitHub Pages 방문자도 키 없이 AI를 쓸 수 있습니다. 아래 '인연노트 AI 서버'를 보세요.
      설치된 대화용 모델을 자동으로 찾아 고를 수 있습니다 (`bge-m3` 같은 임베딩 전용 모델은 뺍니다).
    - 연결이 안 되면 이유를 보여 주고 기본 대화로 이어 갑니다.
  - ⚠️ 브라우저에서 키를 쓰는 방식은 개인 데모용입니다. 키는 그 브라우저에 저장되고 요금은 키 주인에게 청구되니, 공개 배포에서는 서버를 거쳐 호출해야 합니다.
    LLM 호출은 모두 [`js/llm.js`](js/llm.js) 한 곳을 거치므로, 서버로 옮길 때는 이 파일만 바꾸면 됩니다.

**경쟁 앱을 참고해 더한 기능** (모두 AI 없이도 규칙으로 동작하고, AI가 켜져 있으면 더 자연스러워집니다)

| 기능 | 참고한 앱 | 하는 일 | 파일 |
|---|---|---|---|
| AI 중매 상담 | Facebook Dating AI 도우미, Tinder Chemistry | 원하는 분을 말로 설명하면 중요도·거르기 조건·나이·키·스타일 변경안을 이유와 함께 보여 주고, 적용 전후 1~3위를 비교한 뒤 적용·되돌리기 | [`js/concierge.js`](js/concierge.js) |
| 질문 카드 + 한마디 | Hinge Prompts | 질문 카드 2장에 답하고, 상대 카드나 자기소개에 한마디를 남기며 관심을 보냄. 한마디가 있으면 매칭 기준 50점 → 45점, 매칭되면 그 한마디가 첫 메시지 | [`js/prompts.js`](js/prompts.js) |
| 프로필 코치 | Bumble 프로필 가이드, Hinge Prompt Feedback | 사진·자기소개·질문 카드·세부 취향 점검(100점), 막연한 표현·싫은 것 위주 문장 짚기, 고치면 매칭에 무엇이 좋아지는지 안내. AI는 고쳐 쓴 예시 제안 | [`js/coach.js`](js/coach.js) |
| 데이트 제안 · 내 차례 | Hinge Your Turn | 공통 관심사·세부 취향과 사는 곳으로 데이트 코스 3개와 첫 만남 안전 수칙. 채팅 목록에서 내가 답할 차례인 대화를 위로 | [`js/dates.js`](js/dates.js) |
| 만남 후기 | Hinge We Met | "또 보고 싶어요"면 잘 맞았던 항목, "아니었어요"면 고른 이유의 항목 중요도를 한 단계 올림. 상대에게 알리지 않고, 내 정보에서 되돌리기 | [`js/feedback.js`](js/feedback.js) |

기존 데이터(가상 회원 20명의 정보·자기소개·임베딩, 점수표, 저장된 계정)는 그대로이고, 가상 회원에 질문 카드 답만 더했습니다.
예전에 가입한 계정도 새 항목이 비어 있는 채로 그대로 열립니다.

**채팅 안전 검사** ([`js/safety.js`](js/safety.js))
- **보내기 전:** 내 메시지에 전화번호·카톡 아이디, 계좌·송금·투자, 외부 링크, 주민등록번호, 성적인 표현, 욕설이 있으면 이유를 먼저 보여 줍니다.
  같은 메시지를 한 번 더 보내면 그대로 보냅니다.
- **받은 메시지:** 같은 규칙으로 검사하고, 규칙에 걸리지 않으면 AI가 돌려 말한 위험(직장 위치 캐묻기, 투자 권유, 사진 요구 등)을 한 번 더 판단합니다.
  위험하면 메시지 아래에 경고를 붙입니다. AI가 꺼져 있거나 실패하면 규칙 검사만 합니다.

**첫 마디 추천** ([`js/starters.js`](js/starters.js)): 매칭 후 내가 아직 말을 걸지 않았으면 채팅방에 첫 메시지 후보 3개를 보여 줍니다.
공통 관심사·세부 취향·지역으로 바로 만들고, AI가 켜져 있으면 'AI로 맞춤 추천 받기'로 두 사람 자기소개까지 읽은 문장을 받습니다. 누르면 입력칸에 들어가 고쳐서 보낼 수 있습니다.

**돌싱 여부**: 가입할 때 '결혼 경험(미혼 / 돌싱(자녀 없음) / 돌싱(자녀 있음))'을 받고 프로필에 보여줍니다.
절대 조건에 '돌싱이면 제외', '자녀가 있으면 제외'를 켤 수 있습니다(기본은 꺼짐). 점수에는 반영하지 않습니다.

**계정과 프로필 사진**
- 이메일과 비밀번호로 가입·로그인·로그아웃·회원 탈퇴를 할 수 있습니다. 계정마다 프로필, 조건, 보낸 관심이 따로 저장됩니다.
- 비밀번호는 원문을 저장하지 않고, 계정마다 다른 salt를 붙여 PBKDF2(SHA-256, 10만 회)로 해시한 값만 저장합니다.
- 프로필 사진은 가입 중 '프로필 사진' 단계나 '내 정보'에서 올리고 바꿀 수 있습니다. 4:5 비율, 480×600px로 줄여서 저장합니다.
- ⚠️ 서버가 없는 데모라 계정은 **그 브라우저에만** 있습니다. 다른 기기나 브라우저에서는 로그인할 수 없습니다.
  실제 서비스로 만들려면 Firebase Auth 같은 인증 서버가 필요합니다.

입력한 정보는 브라우저(localStorage)에만 저장됩니다. 직업과 학력은 화면에 보여주기만 하고 점수에는 쓰지 않습니다.
추천 결과만 보여주지 않고, **누구를 왜 걸렀는지**, **무엇에 몇 점을 줬는지**,
**1위가 왜 1위인지**를 화면에 문장으로 보여줍니다.

> 이 앱의 핵심은 화면이 아니라 로직입니다. 로직은 화면 코드와 분리해 [`js/matcher.js`](js/matcher.js)에 두었고,
> 점수표는 [`js/rules.js`](js/rules.js) 한 곳에만 적었습니다. 화면과 테스트가 같은 점수표를 함께 씁니다.

## 1. 입력받는 칸

| 칸 | 값 |
|---|---|
| 이름 | 자유 입력 |

| 성적 지향 | 이성애자 / 동성애자 / 양성애자 (프로필 공개·비공개 선택) |
| 나이 | 숫자 |
| 키 | 숫자(cm) |
| 지역 | 서울·경기·인천(수도권), 대전(충청권), 부산·대구(영남권), 광주(호남권) |
| 종교 | 무교 / 기독교 / 천주교 / 불교 |
| 흡연 | 흡연 / 비흡연 |
| 음주 | 안 마심 / 가끔 / 자주 |
| 외모 스타일 | 귀여운 / 단정한 / 시크한 / 스포티한 / 지적인 (본인이 고른 분위기) |
| 관심사 | 등산, 요리, 영화, 독서, 게임, 여행, 카페, 운동, 음악, 사진, 반려동물, 전시회 중 여러 개 |
| 세부 취향 (선택) | 관심사마다 2~7개. 예) 영화: 로맨스·액션·스릴러·공포·SF·판타지·코미디·애니메이션·다큐 / 요리: 한식·양식·일식·베이킹·비건 / 음악: 발라드·K-POP·힙합·인디·밴드·재즈·클래식 |
| 결혼관 | 1~2년 내 / 3~5년 내 / 생각 없음 |

만나는 성별은 따로 고르지 않고 **성별과 성적 지향으로 정해집니다**(아래 표).

| 성적 지향 | 관심 있는 성별 |
|---|---|
| 이성애자 | 나와 다른 성별 |
| 동성애자 | 나와 같은 성별 |
| 양성애자 | 여성과 남성 모두 |

## 2. 거르기: 절대 안 되는 조건

점수를 매기기 **전에** 아래 순서대로 거릅니다. 한 단계에서 걸러진 사람은 다음 단계로 넘어가지 않습니다.
화면에는 단계마다 누가 왜 걸러졌는지 나옵니다.

| 순서 | 조건 | 켜고 끄기 | 왜 |
|---|---|---|---|
| 0 | **나 자신** | 항상 켜짐 | 나를 나에게 추천하면 안 됩니다. 내 프로필도 후보 목록에 넣은 다음, 이 단계에서 확실히 뺍니다. |
| 1 | **서로 관심 있는 성별이 아님** | 항상 켜짐 | 성적 지향을 존중하기 위해 **양방향**으로 확인합니다. 내가 상대의 성별에 관심이 있고, **상대도 내 성별에 관심이 있어야** 추천합니다. 예를 들어 레즈비언 여성에게 이성애자 여성은 추천하지 않습니다. 상대가 지향을 비공개로 했다면 걸러진 이유에도 지향을 적지 않습니다. |
| 2 | 희망 나이 범위 밖 | 직접 선택 | 범위를 정했다는 것 자체가 양보할 수 없는 조건이라는 뜻입니다. |
| 3 | 희망 키 범위 밖 | 직접 선택 | 끄면 걸러지지 않고, 외모 점수 2점에만 반영됩니다. |
| 4 | 흡연자 | 직접 선택 | 비흡연자에게 흡연은 흔한 '절대 불가' 조건입니다. |
| 5 | 나와 종교가 다름 | 직접 선택 | 종교가 꼭 같아야 하는 사람만 켭니다. 끄면 종교 점수 10점에만 반영됩니다. |
| 6 | 나와 다른 권역 | 직접 선택 | 장거리 연애를 원하지 않을 때 켭니다. |
| 7 | 결혼관이 정반대 | 직접 선택 | '1~2년 내'와 '생각 없음'은 만나도 결국 부딪힙니다. |
| 8 | 돌싱 | 직접 선택 (기본 꺼짐) | 이혼 경험이 있는 분을 원하지 않을 때만 켭니다. |
| 9 | 자녀가 있음 | 직접 선택 (기본 꺼짐) | 돌싱이어도 괜찮지만 자녀가 있는 경우는 어려울 때 켭니다. |

**조건을 통과한 사람이 0명이면** 추천 대신 안내 문구가 나옵니다. 가장 많은 사람을 걸러낸 조건을 알려 주고,
그 조건을 끄거나 범위를 넓혀 보라고 제안합니다.

## 3. 점수표: 무엇에 몇 점을, 왜 주는가 (100점 만점)

| 항목 | 만점 | 점수 규칙 | 왜 이 점수인가 |
|---|---:|---|---|
| **관심사** | **35** | 겹치는 관심사 1개당 10점 (최대 35점). 단, 둘 다 세부 취향을 골랐는데 하나도 안 겹치면 그 관심사는 6점 | **가장 중요한 항목**입니다. 공통 관심사가 있어야 첫 대화가 이어지고 함께 할 데이트가 생깁니다. 그래서 다른 항목보다 훨씬 크게 줬습니다. 같은 영화를 좋아해도 장르가 다르면 함께 볼 영화를 고르기 어려워 4점을 덜 줍니다. 한쪽이 세부 취향을 안 골랐다면 따지지 않습니다. |
| 자기소개 | 10 | 소개글의 뜻이 아주 비슷하면 10점, 꽤 비슷하면 6점, 조금 비슷하면 3점 (AI 문장 임베딩, 아래 설명) | 같은 단어를 고르지 않아도 좋아하는 하루, 데이트 분위기가 닮은 사람을 찾습니다. 짧은 글로 판단하므로 비중은 작게 뒀습니다. |
| 결혼관 | 15 | 같으면 15점, 한 단계 차이 7점, 정반대 0점 | 관계의 방향이 맞는지를 봅니다. 장기적으로는 중요하지만 첫 만남의 재미보다는 뒤에 둡니다. |
| 외모 | 5 | 내가 고른 선호 스타일이면 3점 + 키가 희망 범위 안이면 2점 | 첫인상은 중요하지만 사진만으로 판단하기 어려워서 비중을 낮췄습니다. 본인이 고른 스타일보다 직접 쓴 자기소개가 더 많은 걸 알려 주므로, 자기소개 항목을 만들면서 5점을 그쪽으로 옮겼습니다. |
| 거리 | 10 | 같은 지역 10점, 같은 권역 5점, 그 밖 0점 | 자주 만날 수 있어야 관계가 이어집니다. |
| 나이 차 | 10 | 2살 이내 10점, 4살 이내 6점, 6살 이내 3점 | 나이가 비슷하면 겪는 일과 문화가 비슷해 공감대가 생기기 쉽습니다. |
| 종교 | 10 | 같으면 10점 | 종교가 같으면 생활 방식과 가치관이 겹칠 가능성이 큽니다. |
| 생활습관 | 5 | 흡연 여부가 같으면 3점 + 음주 빈도가 같으면 2점 | 데이트할 때 바로 드러나는 습관이지만, 맞춰 갈 수 있는 부분이라 작게 줬습니다. |
| **합계** | **100** | | |

### 내가 정하는 가중치 (항목별 중요도)

위 점수표는 모든 항목이 '보통'일 때의 기본값입니다. '리포트' 탭의 점수표에서 항목마다 중요도를 고를 수 있습니다.

| 중요도 | 안 봄 | 조금 | 보통 | 중요 | 매우 중요 |
|---|---|---|---|---|---|
| 배수 | ×0 | ×0.5 | ×1 | ×2 | ×3 |

1. 각 항목의 기본 만점에 배수를 곱합니다.
2. 합이 100이 되도록 비례로 다시 나눕니다. 반올림으로 남는 점수는 소수점이 큰 항목부터 1점씩 채웁니다.
3. 상대가 받은 점수도 같은 비율로 바꿉니다. 예: 공통 관심사 3개는 기본 30/35점 = 6/7입니다.

예를 들어 관심사만 '매우 중요'로 하면 관심사 만점은 35점에서 **61점**이 됩니다(나머지 항목은 줄어듦). 공통 관심사가 3개인 상대는 그중 6/7인 52점을 받습니다.
바꾸면 순위, 1위 이유, 매칭(50점 기준)이 바로 다시 계산되고, 1위 이유에 "내가 정한 중요도가 반영됐어요" 문장이 붙습니다.

### 자기소개 비교 (문장 임베딩)

자기소개를 AI 문장 임베딩 모델([`Xenova/multilingual-e5-small`](https://huggingface.co/Xenova/multilingual-e5-small), 한국어 지원)로 384차원 벡터로 바꾸고, 두 벡터의 코사인 유사도로 뜻이 얼마나 비슷한지 봅니다.

- **가상 회원 20명**의 벡터는 미리 계산해 [`js/embeddings.js`](js/embeddings.js)에 넣어 두었습니다 (`npm run embeddings`).
- **내 소개글**은 브라우저 안에서 [Transformers.js](https://huggingface.co/docs/transformers.js)로 계산하고, 소개글을 밖으로 보내지 않습니다. 처음 한 번 모델 파일(약 135MB)을 내려받는 동안에는 자기소개 항목을 빼고 나머지 항목으로 100점을 나눠 추천합니다. 계산이 끝나면 바로 다시 계산하고, 결과는 계정에 저장합니다.
- 미리 계산할 때와 브라우저에서 계산할 때 모두 [`js/intro-embed.js`](js/intro-embed.js)를 씁니다. 그래서 모델, 접두어(`query: `), 문장 나누기가 같습니다.
- **평균 벡터를 뺍니다.** 이 모델은 관련 없는 문장끼리도 유사도가 0.8 이상 나옵니다. 20명 소개글의 평균을 빼야 말투나 문장 모양이 아니라 내용의 차이가 드러납니다(보정 뒤 회원끼리 유사도는 -0.29~0.25).
- **점수 구간**은 회원 190쌍의 분포로 정했습니다: 0.18 이상(상위 약 3%) 10점, 0.10 이상(상위 약 10%) 6점, 0.03 이상(상위 약 20%) 3점. 숫자는 [`js/rules.js`](js/rules.js)에 있습니다.
- **근거:** 점수를 받으면 서로 가장 닮은 문장 한 쌍을 함께 보여줍니다. 예) "자기소개가 아주 비슷해요 (유사도 0.25): 「미술관 데이트 좋아해요.」 ↔ 나 「조용한 데이트를 좋아해요.」"
- **한계:** 작은 모델이라 '산 정상에서 끓이는 라면'과 '등산 끝나고 맛집'처럼 한 단계 건너 이어지는 뜻은 잘 잇지 못합니다. 소개글이 짧을수록 정확도가 떨어져서 가입 화면에서 2~3문장을 권합니다.
- `profiles.js`의 소개글을 고치면 `npm run embeddings`로 다시 만들어야 합니다. 그러지 않으면 그 회원은 비교에서 빠지고, 테스트가 실패해서 알려 줍니다.

### 동점일 때

1. 총점이 높은 사람
2. 총점이 같으면 겹치는 **관심사 개수**가 많은 사람(최우선 항목)
3. 그것도 같으면 **나이 차**가 적은 사람
4. 그것도 같으면 이름 가나다순

## 4. 이유: 왜 이 사람이 1위인가

화면 맨 위의 1위 카드가 다음 내용을 문장으로 설명합니다.

- 1위의 총점과, 2위보다 몇 점 높은지
- **항목별로 2위보다 앞선 점수와 그 근거** (예: "관심사 +10점: 등산·요리·영화 3개 겹침(30점) vs 2위는 2개(20점)")
- 2위에게 진 항목이 있으면 그것도 밝히고, 다른 항목에서 더 앞서서 1위가 됐다고 설명합니다.
- 동점이면 어떤 동점 규칙으로 순위가 갈렸는지
- 통과한 사람이 한 명뿐이면 그 사실

## 실행 방법

빌드 과정이 없습니다. `index.html`을 브라우저로 열면 바로 실행됩니다.

```bash
# 로직 테스트 (Node.js 22 이상)
npm test

# 가상 회원 소개글을 고쳤다면 임베딩 다시 만들기 (처음엔 모델을 내려받음)
npm install
npm run embeddings              # js/embeddings.js 저장
npm run embeddings -- --table   # 회원끼리 유사도 표만 보기
```

### GitHub Pages로 배포하기

git init
git add .
git commit -m "인연노트 소개팅 앱"
git branch -M main
git remote add origin https://github.com/<내 아이디>/inyeon-note.git

### 로컬 AI (Ollama) 연결하기

```bash
ollama pull llama3.1:8b   # 대화용 모델 하나 받기 (한국어에 강한 모델일수록 대화가 자연스럽습니다)
npx serve .               # http://localhost:3000 같은 주소로 열기
```

- **localhost에서 연 페이지**는 Ollama가 기본으로 허용합니다. '내 정보 → AI 대화 설정 → 로컬 AI'를 고르면 됩니다.
- **`index.html`을 더블클릭해 연 페이지**(`file://`)는 Ollama가 막습니다. 위처럼 로컬 서버로 열어 주세요.
- **GitHub Pages에서** 내 PC의 Ollama를 쓰려면, Ollama를 켜기 전에 사이트 주소를 허용해야 합니다.
  Windows는 `setx OLLAMA_ORIGINS "https://<내 아이디>.github.io"`를 실행한 뒤 Ollama를 다시 켭니다.
  이 설정은 **내 PC에서만** 효과가 있습니다. 다른 방문자에게는 로컬 AI가 연결되지 않고 기본 대화와 규칙 검사로 동작합니다.

### 인연노트 AI 서버: 방문자 모두가 내 Ollama를 쓰게 하기

[`server/ai-server.mjs`](server/ai-server.mjs)는 Ollama 앞에 두는 작은 API 서버입니다. 외부 라이브러리 없이 Node만으로 돕니다.
Ollama를 그대로 인터넷에 열면 누구나 모델을 받거나 지울 수 있어서, 이 서버는 **정해진 모델로 답장 만들기 하나만** 열어 줍니다.

| 주소 | 하는 일 |
|---|---|
| `POST /v1/complete` | `{ system, messages, maxTokens?, json? }` → `{ text }` |
| `GET /health` | `{ ok, model, ollama }` (Ollama가 켜져 있고 모델이 있는지) |

막는 것: 허용 목록에 없는 사이트, IP당 1분 20번 초과, 큰 요청(본문 64KB, 메시지 40개, 메시지 하나 2,000자), 요청으로 모델 바꾸기,
1,024토큰을 넘는 답장, Ollama의 다른 기능(`/api/pull`, `/api/delete` 등). Ollama는 한 번에 하나씩 답하므로 요청은 줄을 세우고, 8개 넘게 밀리면 거절합니다.

```powershell
npm run ai-server   # 내 PC에서만 쓰기: http://127.0.0.1:8787
npm run ai-public   # 인터넷에 열기: 서버 + Cloudflare 무료 터널을 함께 켜고 https://….trycloudflare.com 주소를 알려 줌
```

`ai-public`은 무료이고 가입이 필요 없습니다([cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) 설치만 필요:
`winget install Cloudflare.cloudflared`). 켜기 전에 Ollama와 모델을 확인하고, 같은 포트에 다른 서버가 떠 있으면 멈춥니다.
허용 사이트에는 `https://threeat.github.io`가 들어 있습니다 ([`server/ai-public.mjs`](server/ai-public.mjs)의 `SITE`).

**공개해도 안전하게 해 둔 것** (2026-10-21 공개 주소로 직접 확인)

| 위험 | 막는 방법 | 확인 결과 |
|---|---|---|
| 집 공유기·IP 노출 | 터널은 PC에서 Cloudflare로 나가는 연결이라 포트를 열지 않음 | 방문자에게는 Cloudflare 주소만 보임 |
| 같은 와이파이의 다른 기기 접속 | 서버는 `127.0.0.1`에서만 받음 | 내부 IP로 접속하면 연결 거부 |
| 모델 받기·지우기 | `/v1/complete`, `/health` 말고는 없음 | `/api/pull`, `/api/delete` → 404 |
| 다른 사이트가 몰래 호출 | 허용 목록에 없는 사이트는 403 | `evil.example` → 403 |
| 한 사람이 GPU를 독차지 | IP당 1분 20번, 전체 1분 120번, 대기 8개 | 21번째부터 429 |
| IP를 속여 제한 피하기 | 터널 뒤에서만 Cloudflare IP 헤더를 믿음 | 헤더를 꾸민 요청은 Cloudflare가 거절 |
| 대화 내용 유출 | 서버는 대화를 저장하거나 기록하지 않음, 응답 캐시 금지 | |

| 환경변수 | 기본값 | 뜻 |
|---|---|---|
| `MODEL` | `llama3.1:8b` | 답장에 쓸 Ollama 모델 |
| `ALLOWED_ORIGINS` | `http://localhost:*,http://127.0.0.1:*` | 호출을 허용할 페이지 주소 (쉼표로 구분) |
| `RATE_LIMIT` | `20` | IP 하나가 1분에 보낼 수 있는 요청 수 |
| `GLOBAL_RATE_LIMIT` | `120` | 모든 IP를 합쳐 1분에 받는 요청 수 |
| `HOST` | `127.0.0.1` | 요청을 받을 주소. 바꾸지 마세요 (같은 와이파이에 열림) |
| `ACCESS_KEY` | 없음 | 정하면 앱 설정에 같은 키를 넣은 사람만 쓸 수 있음 |
| `TRUST_CF_IP` | 꺼짐 | Cloudflare Tunnel 뒤에서만 `1` (`ai-public`은 자동으로 켬). 터널 없이 켜면 IP를 속여 횟수 제한을 피할 수 있음 |
| `PORT` · `OLLAMA_URL` | `8787` · `http://localhost:11434` | 서버 포트와 Ollama 주소 |

앱에서는 '내 정보 → AI 대화 설정 → AI 서버'에 터널 주소를 넣습니다. 방문자가 아무 설정 없이 처음부터 쓰게 하려면
[`js/llm.js`](js/llm.js)의 `AI_SERVER_URL`에 주소를 적고 다시 배포하세요.

- ⚠️ 서버를 연 PC가 켜져 있고 Ollama와 서버, 터널이 모두 돌고 있어야 방문자가 AI를 쓸 수 있습니다. PC가 꺼지면 앱은 기본 대화로 돌아갑니다.
- ⚠️ 방문자의 대화가 서버를 연 PC로 보내집니다. 실제 서비스라면 개인정보 처리방침에 적고 동의를 받아야 합니다.
- ⚠️ `trycloudflare.com` 주소는 터널을 다시 켤 때마다 바뀝니다. 고정 주소가 필요하면 Cloudflare 계정에 도메인을 연결한 이름 있는 터널을 쓰세요.
- `ACCESS_KEY`는 GitHub Pages 코드에 넣으면 누구나 볼 수 있으니, 공개용이 아니라 나와 지인만 쓰게 할 때 쓰세요.
