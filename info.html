테두리가 보라색인 단계에서 LLM이 쓰입니다.

모든 LLM 호출은 한 길로 지나간다

다섯 기능은 LLM을 직접 부르지 않고 llm.js의 complete() 하나만 부릅니다. 어느 모델을 쓰든, 실패하든, 기능 코드는 같습니다.

① 기능이 요청을 만든다

시스템 프롬프트 + 대화

  • 기능마다 역할과 규칙을 적은 시스템 프롬프트
  • 필요한 프로필 정보만 골라 넣음
  • 판단·추천은 JSON으로 답하라고 요구
  • 답 길이 상한 300~2,000토큰

믿기 전에 확인

  • 앞뒤 군말이 있어도 첫 JSON 덩어리만 꺼냄
  • 허용한 키와 범위 안의 값만 남김 (중매 상담)
  • 빈 답·모양이 틀린 답은 실패로 처리
→

④ 화면에 보여 준다

사용자가 마지막에 고른다

  • AI가 만든 것은 "AI 해석", "AI 판단"으로 표시
  • 조건 변경·자기소개 예시는 바로 저장하지 않음
  • 적용 전 미리 보기, 적용 후 되돌리기
실패하면 AI가 꺼져 있거나, 연결이 안 되거나, 답이 이상하면 → 같은 기능의 규칙 버전으로 이어 가고, 필요하면 실패 이유를 화면에 적습니다. 그래서 AI 없이도 앱 전체가 동작합니다.

일부러 LLM을 쓰지 않은 곳

점수와 판정은 규칙이 맡는다

LLM 없이 규칙으로

  • 거르기 조건 10개, 궁합 점수 8항목, 순위와 동점 규칙
  • "왜 이 분이 1위인가요?" 설명 문장
  • 매칭 판정 (50점, 한마디가 있으면 45점)
  • 보내기 전 안전 검사 (보내기가 늦어지지 않게)
  • 데이트 코스 제안 (가게 이름을 지어내지 않게)
  • 만남 후기로 중요도 조정

이유

  • 설명할 수 있어야 한다. "왜 이 사람이 1위인지"를 숫자와 문장으로 보여 주는 게 이 앱의 약속이라, 점수는 같은 입력에 늘 같은 답을 내는 규칙이 매깁니다.
  • LLM은 점수를 바꾸지 않고 장치를 고른다. 중매 상담도 새 규칙을 만들지 않고, 이미 있는 중요도·조건만 바꾸자고 제안합니다. 그래서 바뀐 순위도 리포트로 설명됩니다.
  • 지어내면 안 되는 곳은 규칙. 데이트 장소처럼 LLM이 그럴듯하게 지어낼 수 있는 곳은 활동과 동선만 제안합니다.
